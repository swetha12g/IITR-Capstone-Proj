# PipelineFortress v1.0.0

First project release of PipelineFortress, a DevSecOps training implementation around OWASP Juice Shop with guarded AI assisted triage. The release consolidates the capstone implementation and the three focused infrastructure remediation PRs through `feature-16-kick-start`, `develop` and `main`.

## Included capabilities

- GitHub Actions coverage for SAST, SCA, secrets, IaC, container scanning and passive DAST, with hash-bound receipts and an authoritative aggregate verdict.
- A hardened container build, exact-image runtime checks and Syft CycloneDX inventory generation.
- Source-free AI payload construction, refusal before transport, deterministic output grounding and a reproducible mock mode.
- A metrics dashboard, deferred-risk register, twelve-page study report, pinned tools and full-history reproduction instructions.
- The three baseline deployment controls: disable service-account token mounting, require non-root execution with UID/GID 65532, and add a bounded HTTP liveness probe.
- Promotion-branch CI and tag-driven release publication, restricted to the current `main` revision after successful complete study CI.

## Verification and scope

The existing accepted publication run records 2,332 selected application passes, six skips, complete expected server-case coverage, 85 safeguard contracts and zero critical observations. These are historical execution results tied to their original revision. Release-candidate verification and new hosted results are recorded separately in `docs/release-promotion.md`; a tag is published only after the promoted main revision passes the complete study workflow.

Source history and the release notes accompany the GitHub-generated source archives. The locally prepared `Final-Submission` video/report/container package is preserved separately and is not silently added to Git history or represented as a release asset.

## Known limitations

- High and lower security findings remain deferred in the owned training lab. A successful study workflow does not establish production readiness or absence of vulnerabilities.
- The external triage client has no successful live evaluation after three historical HTTP 429 attempts. Mock results do not establish model accuracy or actual billed usage.
- Detection metrics use a small post-hoc curated fixture set. Independent labeling and genuine independent PR review remain unverified. Owner-directed merging does not create an independent approving review.
- DAST is passive and unauthenticated. NetworkPolicy enforcement and full CIS benchmark compliance are unproven.
- Historical source approvals expired on 25 October 2026. This release does not renew them or establish program deadline, oral-defense or submission acceptance.

No external runtime deployment or new AI provider request is part of this release. Use the project only in the documented owned training environment.
